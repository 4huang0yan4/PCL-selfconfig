## 为什么存在这套文件

1. **上下文窗口有限**：设计细节、字段表、参考笔记放进对话会挤掉真正要用的工作记忆。
2. **记忆库只装结论**：`xiangmu/pcl-shiguang-qidongqi` 存"是什么、坑在哪、路径在哪"，几百字讲完；长内容放这里。
3. **可版本化**：目录可直接 `git init`，每次改动有记录，出问题能回滚，也能人工审阅。

## 使用约定

1. **开工**：读 `INDEX.md` → 读当前任务对应的 1–2 个文件 → 再动手。需要确切旧结论时另查记忆库。
2. **讨论中**：口头的决定立刻写进对应文件，不攒着。攒着就会在下一轮丢失，然后重复讨论。
3. **收工**：更新 `08-todo-risks.md`（今天做了什么、什么没验证），必要时更新 `INDEX.md` 的状态列。
4. **粒度**：一个文件只讲一件事；单文件超过 **200 行**就拆分。跨文件拼凑会抵消按需加载的收益。
5. **状态标记**：每条结论必须带其一 —— `[已确认]`（实测或读到源码）、`[待测试]`（**功能已实现、单机能跑，只差真实环境跑一次**）、`[待验证]`（**事实本身未知，需查资料/读源码**）、`[待决策]`（需人拍板）、`[已废弃]`（保留说明为何废弃）。
   - `[待测试]` 与 `[待验证]` 都**不是**通过，别混为一谈。全部待测试项集中在 `08-todo-risks.md` 第二节（T-01 起编号）。
6. **清理**：定期把过期条目移到 `archive/`，不留在主文件里。过期信息比没有信息更糟——它会引导错误决策。
