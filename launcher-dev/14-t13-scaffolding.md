# 14 T-13：Scaffolding 互通实测（PCL CE ↔ 陶瓦）

状态：`[✅ 已通过 2026-10-30，双向互通]`（2026-10-30 建、当日实测通过）
依赖：PCL CE 便携版（`PCL-Community/PCL-CE` v2.15.1，`PCL2_CE_Release_x64.exe`，22.4 MB）；本机陶瓦 0.4.2；第二台机或 VM
依据：`02` 的 R7、`03-references.md` 的 Scaffolding 节、`08` 的 T-13

---

## 一、结论先说

陶瓦 0.4.2 **就是 Scaffolding 联机中心**：源码 `src/scaffolding/server.rs`，本机二进制内可直接 grep 到 `scaffolding-mc-server`。PCL CE 有完整客户端（`PCL.Core/Link/Scaffolding/`）。
所以本项**不是实现协议**，而是确认「第三方客户端能否发现并加入陶瓦房间」。失败也只可能是环境/版本，不是缺功能。

## 二、前提与风险

- **必须分机**：陶瓦用全局文件锁（`%TEMP%\terracotta\terracotta.lock`），一台机器只能有一个守护进程、一份状态。PCL CE 与 PCL 同机同时建房会互相抢锁。
- **版本一致**：陶瓦 v0.4.2 起移除旧房间格式；PCL CE 用最新 v2.15.1。
- **取证边界**：陶瓦 HTTP 只绑 `127.0.0.1`，智能体读不到另一台机的内部状态。只能看①本机 `/state`、②本机 `PCL\Log1.txt`、③PCL CE 侧日志（需要用户截图或导日志）。
- **别让 PCL CE 自己起陶瓦**：若 PCL CE 内置联机模块会拉起独立 EasyTier，注意它不要与本机陶瓦同网段抢中心。

### 2026-10-30 实测前提修正（用户在 VM 里截的 CE 界面）

CE v2.15.1 的联机 UI **不是**裸露的 Scaffolding 客户端，而是**「Natayark Network 大厅」**（工具 → 联机 → 大厅）：有「点击测试」「登录 Natayark 账户」「加入大厅」「创建大厅」，底部友情链接为 EasyTier 官网与 Pysio's Home。设置 → 联机 里只有 **EasyTier** 参数（用户名、协议偏好 TCP、对等发现、IPv6），**没有中心地址配置项**。

关键比对——**房间码格式完全相同**：

| | 格式 | 示例 |
|---|---|---|
| 陶瓦 0.4.2 | `U/XXXX-XXXX-XXXX-XXXX`，21 字符，34 进制 + 能被 7 整除的校验位 | `U/D8P6-1PM5-ZQEQ-EYY8` |
| CE 大厅编号 | `U/NNNN-AAAA-SSSS-EEEE` | 界面提示原文 |

**所以协议是同一个（Scaffolding），真正的变量是「中心」**：房间码只是 16 位房间 ID，**不含中心地址**（见 `06` 第七节）。CE 的中心按 UI 看是硬编码的 Natayark，陶瓦则用自己内置的 `scaffolding-mc-server`。两端房间码能互相校验通过，但可能各自去**不同的中心**查同一个房间号 → 这才是最可能的失败点，不是协议不兼容。

**另注**：`c:protocols` / `c:server_port` 在陶瓦二进制里 grep 命中 0（只在 CE 客户端侧出现），所以在陶瓦侧查这两个字段没有意义，取证要在 CE 日志里找。

**由此调整的测法**：先拿「CE 连的是哪个中心地址」，再决定用哪种方式互通。若陶瓦的 `public_nodes` 能填 CE 的中心地址，则有希望打通；否则 T-13 的结论就是"同协议、不同中心，需第三方中心才能互通"，按此写回 `08` 与 `02` 的 R7。

## 三、步骤

> **2026-10-30 用户定的分工（与初稿相反，以此为准）**：**自编版 PCL 放虚拟机当房主，PCL CE 放本地当游客。**
> 理由：CE 需要正版账号登录，本地登录更方便；而且 **CE 在本地 → 智能体能直接读它的日志，拿到「CE 连的是哪个中心地址」** —— 这正是本项最关键的一条证据。
> 代价：自编版在 VM 里，智能体读不到陶瓦 `/state`（陶瓦只绑 `127.0.0.1`）。宿主侧取证靠用户口述或把 VM 的 `PCL\Log1.txt` 丢进共享文件夹。

### A. 虚拟机（自编版 PCL，房主）

1. 把**最新** `PCL-custom\Plain Craft Launcher 2.exe`（`custom.31`）复制进 VM 覆盖旧的；`PCL\Terracotta\` 里的 `terracotta-0.4.2-windows-x86_64.exe` + `VCRUNTIME140.DLL` 保持同目录。
2. 用**完全权限**启动（沙箱会误报「没有对当前文件夹的权限」）。
3. 进游戏世界 → 「对局域网开放」。
4. 联机页 → 建房，等 `host-ok` 出码，**记下房间码（`U/....`）与时间**，念给智能体或贴到共享文件夹。

### B. 本机（PCL CE v2.15.1，游客）

5. 运行 `<下载目录>\PCL2_CE_Release_x64.exe`（单文件免安装）。
6. **登录 Natayark 账户**（必须，否则大厅列表都看不了）；先点「点击测试」记下结果原文。
7. 工具 → 联机 → 大厅 → 「加入大厅」→ 输入 A 步的 `U/....` 房间码 → 加入。

### C. 取证

- **本机（关键）**：CE 的日志。找 `PCL\Log*.txt`（exe 同目录或 `%APPDATA%\PCL`），搜 `Scaffolding` / `scaffolding-mc-server` / `c:server_port` / 中心域名。**要拿到它请求的中心地址**。
- **本机**：`netstat -ano` 看 CE 进程连出去的远端地址（另一个拿中心地址的办法，不依赖它的日志格式）。
- **VM 侧**：用户口述状态行，或把 `PCL\Log1.txt` 丢进共享文件夹；日志里搜 `陶瓦` / `terracotta`。

## 四、判据

| 结果 | 判据 |
|---|---|
| ✅ 通过 | PCL CE 进到宿主世界；本机 `/state` 出现 guest；游戏内互相可见 |
| ❌ 失败·中心发现 | PCL CE 报找不到联机中心 / `scaffolding-mc-server` 解析失败 |
| ❌ 失败·TCP | 发现中心但连接超时 → 查防火墙与 UDP/TCP 端口，别先怀疑协议 |
| ❌ 失败·协议 | `c:protocols` / `c:server_port` 返回非 0 状态码 |
| ❌ 失败·版本 | 房间码格式被拒 → 双方版本不一致 |

### 实测观察（下次复现要对得上的）

- CE 侧把陶瓦端显示为 **`Terracotta Anonymous Host` / `Terracotta Anonymous Guest`** —— 陶瓦不上报用户名，所以是匿名的。**这不是故障**，别当成"另一个客户端没识别出来"。
- 两端 EasyTier 版本**不同也能通**：陶瓦内嵌 `v2.5.0-terracotta.2`，CE 用 `2.6.4`。说明互通不依赖 EasyTier 版本对齐。
- CE 大厅顶部有一条常驻提示「联机服务对您的网络质量要求较高，如遇连接不上可尝试更换房主」——那是 Natayark 中心自己的文案，与本分支无关。
- 房间里 `Delay` 显示 9 ms（同一局域网/VM 桥接下）。

**这意味着什么**：本分支的陶瓦联机不再只服务"两个都用 PCL-拾光的人"。**对方装 PCL CE（或任何实现了 Scaffolding 的启动器）就能进同一个房间，且陶瓦这一侧不需要登录任何账户**。R7 当初要的"与第三方启动器互通"，到这里算实证成立。

### 互通边界（按组合列清，别把结论说过头）

| 组合 | 局域网 | 跨公网 |
|---|---|---|
| 自编版 ↔ 自编版 | ✅ | **✅**（用户实测） |
| 自编版 ↔ HMCL | ✅ | **✅**（2026-10-30 用户实测，在做 CE 测试卡住时顺手做的） |
| 自编版 ↔ PCL CE | ✅ | ❌（CE 侧 `--p2p-only`，见第七节） |

**可对外说的口径**：以陶瓦为主的启动器都能互加——HMCL、FCL、ZL2、FMCL、MoLaunch、Axolotl 等都是**直接内置陶瓦**，
与自编版同一内核，跨网也不受本分支限制。**PCL CE 是唯一例外**：它走 Scaffolding 协议互通，局域网可连、跨网受它自己的
`--p2p-only` 限制（不接受中继）。

**仍缺**：游戏内实际互相可见性没有截图（现有证据都是启动器侧成员列表）。

## 七、跨网失败根因与 P2P 可行性

> 已移到 `14b-crossnet.md`：CE 的  证据、四组实测数据、节点对照、CE 侧可调项已清零、P2P 增强（UPnP/自建节点）为何做不了。
