# 01 定位与边界

状态：`[已确认]`（2026-10-27 与用户确认）
最后更新：2026-10-27

---

## 一句话定位

**纯自用、全功能、兼容广的 Minecraft 启动器**：以自编版为核心，PCL 作为底座与备选参考；非必要不依赖 PCL 官方后续更新。

## 三条主线

1. **自主可控**：下载、安装、启动、导出这些核心链路的实现要掌握在自己代码里，不靠对官方二进制的补丁维持。
2. **兼容优先**：整合包、实例、联机三处都对齐社区既有标准，不发明私有格式。迁移能力来自"能读懂别人的格式"，不是"能导出自己的格式"。
3. **长期可维护**：项目是**不定时更新**的长期工程，不做一次性 hack。任何临时手段都要在文档里标注退役条件。

## 与 PCL 的关系

| 层面 | 当前做法 | 说明 |
|---|---|---|
| 代码基座 | 基于 PCL 2.99.0.0 开源版自编译（`pcl-src\`） | 已解除下载限制：`RestrictMcDownload=False` 是**源码常量**，不是二进制补丁 |
| 自用功能 | `Modules\ModCustom.vb` + `custom\` 覆盖层（23 文件） | 主题解锁、百宝箱、凭据卡、下载源、视频背景、联机页 |
| 官方后续 | 不依赖 | 官方已明确不恢复 MC 下载功能，分支自行演进 |
| 上游同步 | `sync.cmd` 按需拉 tag | 同步后 23 个覆盖文件需人工比对 |

> 关键区别：本项目的"下载恢复"来自改源码常量后重编译，**不是** IL 重写官方 exe。前者可持续维护，后者每次官方更新都失效。

## 做什么

- 版本隔离、实例级 Java 指定
- 整合包导入导出（MCBBS v2 优先，`.mrpack` 次之）
- 联机（先接成熟方案，后做可插拔抽象）
- 构建期安全检测（Roslyn 分析器、依赖漏洞扫描）
- 界面与体验的持续打磨（主题、帮助、快捷入口）

## 不做什么

| 不做 | 原因 |
|---|---|
| 公开发布 / 上架 | 2026-10-27 定调：纯个人自用。因此不必受 PCL《存储库合理使用指南》约束（名称前缀、蓝主色、赞助劝导等） |
| 跨平台（Linux/macOS） | 目标环境仅 Windows 10+；跨平台会迫使重写平台层，投入产出不划算 |
| 自研启动核心（游戏进程管理） | 已有实现成熟，重写无收益；精力放在兼容与联机上 |
| 发明私有整合包格式 | 与"兼容优先"冲突；任何新格式都必须先有社区标准 |
| 修改官方 exe 做长期方案 | 每次官方更新即失效，且无法定位问题 |

## 成功标准

1. 换一台干净的 Win10，拷 `gongtong\` 目录 + JDK，能编译、能启动、能下载一个版本并进游戏。`[已确认]`（本机已验证编译与启动；干净机器未验证 `[待验证]`）
2. 能把一个整合包在 PCL 分支与 HMCL 之间双向迁移，不丢模组与配置。`[待验证]`
3. 联机不依赖单一服务，方案可以在不改主程序的前提下替换。`[待决策]`（抽象层尚未设计）
4. 断网环境下 `dotnet build` 能成功（工具链与 NuGet 缓存自带）。`[待验证]`

## 优先级原则

功能取舍时按此排序：**能进游戏 > 能装整合包 > 能联机 > 能迁移 > 安全与体验**。
理由：前两项是刚需，后两项是增值；顺序倒过来会出现"界面很漂亮但装不上包"的情况。

## 许可注意（自用也需知）

- 自用不分发，AGPL 类条款（如 Terracotta）不触发"传染"；但**一旦对外分发二进制**，打包方式就必须按 AGPL 处理。当前不发布，风险为零；若将来改变定调，先读 `03-references.md` 的许可列。
- PCL 主体代码有自定义许可，`PCL CE` 是混合许可，移植任何文件前逐文件确认。详见 `03-references.md`。
