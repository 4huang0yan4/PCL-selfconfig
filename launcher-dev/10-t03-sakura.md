# 10 T-03：陶瓦与樱花穿透并存

状态：`[已确认]` **通过**（2026-10-28 单机部分全过，S0–S4）。樱花穿透常驻（`SakuraLauncher.exe` / `SakuraFrpService.exe`），隧道可正常建立与断开。
最后更新：2026-10-28

> 为什么这项要紧：`08` 的风险 R-04 写的是"联机方案锁死单一后端，后端改接口即全瘫"，缓解措施之一是**保留樱花穿透降级路径**。
> 如果两者根本不能共存，这条降级路径就是纸面上的，等于只有一个后端。
> **单机可测**：不需要 VM，看的是端口/组播/进程是否互抢，而不是游客端体验。

## 一、冲突面（先想清楚再对现象）

- **陶瓦**：用 UDP `4445` 组播找局域网世界；起一个本地 HTTP 端口，端口号写在 `%TEMP%\terracotta\terracotta.lock` 前 2 字节；全局文件锁保证一台机器只有一个守护进程。
- **樱花穿透**：`frpc` 连远端节点，把本机某个端口转发出去（多按 TCP，也可 UDP）。
- 三处可能真撞：① `4445` 被樱花映射占用；② 樱花映射的本机端口与陶瓦 HTTP 端口相同；③ 两者都要独占 socket / 组播成员资格。

## 二、步骤（每步停下核对，再进下一步）

| 步 | 操作 | 要记录 |
|---|---|---|
| S0 | 基线：陶瓦未起、樱花未连 | 已记：无 `frpc`、无 `4445` 监听 |
| S1 | 在樱花里连上一个隧道（映射本机 `25565` TCP），等状态「已连接」 | 隧道类型（TCP/UDP）、本地端口、远端地址端口 |
| S2 | **隧道保持连接**，游戏内「对局域网开放」→ 启动器「建房」 | 是否出码、耗时秒数、有无端口/绑定错误 |
| S3 | 查冲突证据 | `netstat -ano` 里 `4445` 与 `frpc` 占用的本地端口；陶瓦 `/meta` 是否可达；`terracotta.lock` 里的端口 |
| S4 | **反向顺序**：断隧道、停联机 → 先建房出码成功 → 再连隧道 | 房间码是否仍有效、陶瓦是否掉线、游客能否加入 |
| S5 | 可选加强：VM 当游客加入 | 同开樱花与陶瓦时联机是否仍通（这时 T-03 与 T-01 一起过） |

## 三、判定

- **通过**：S2 正常出码、S3 无端口冲突、S4 房间码不失效。
- **不通过**：任一步出现端口占用报错、房间码失效、或陶瓦守护进程退出。
- 结论写回 `08` 第二节 T-03、以及 `06-multiplayer.md` 的实测记录。

## 四、实测记录（2026-10-28）

| 步 | 实测 | 结论 |
|---|---|---|
| S0 | 樱花常驻、隧道未连；无 `frpc`、无 `4445` 监听 | 基线干净 |
| S1 | 隧道连上：`frpc.exe` 新起，绑定 **UDP `4445`**（`0.0.0.0` ×2 + `[::]`），连 `103.91.208.133:80` | 隧道确实占了 4445 |
| S2 | 隧道保持连接时建房：14:29:11 点「创建房间」→ 15:29:13 守护进程就绪（`17034`）→ `/state` = `host-ok`，房间码 `U/5WZ9-9YFC-WP88-L92T` | **出码成功**，2.3 秒 |
| S3 | `4445` 全程只有 `frpc` 持有；陶瓦监听 `13448`（`yggdrasil_port`）+ `127.0.0.1:17034` | **无端口冲突** |
| S4 | 复位 → 断隧道 → 重新建房出码 `U/DB80-DBX4-90LK-CAVA` → 再连隧道（`frpc` 新 PID）：`/state` 仍 `host-ok`，守护进程 PID 未变 | **房间码不失效、不掉线** |

**关键结论**：陶瓦 0.4.2 底层是 **EasyTier v2.5.0** 组网（`embedded-easytier-core.exe`，`/meta` 里 `yggdrasil_port=13448`），**并不独占 UDP 4445**——所以 `frpc` 占着 4445 互不干扰。`4445` 只是 Minecraft 局域网广播用的端口，陶瓦以组播加入方式接收，不需要独占绑定。R-04 的"樱花降级路径"因此**成立**。

## 五、已知陷阱

- 陶瓦建房前**必须先在游戏里「对局域网开放」**，否则永久停在 `host-scanning`——别把"没开局域网"误判成樱花抢端口。
- 陶瓦 `/panic?peaceful=true` 不回响应（服务端直接 `exit(0)`），连接重置属正常。
- 访问 `127.0.0.1` 要显式禁代理，否则系统代理会返回**假 502**，看起来像服务挂了。
- 樱花若用 TUN/虚拟网卡模式，可能与组播冲突，且需要管理员权限；先用普通隧道模式测，TUN 单列。
