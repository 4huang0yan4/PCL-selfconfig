## A. 本轮新加的功能

### T-A1 外置登录入口（custom.12）

1. 打开首页左侧「开始游戏」上方，看登录区是否有 **三个** 切换按钮：`正版` / `离线` / `第三方`
2. 点 `第三方`

**通过判据**：
- 出现第三方登录页（外置登录）
- 页面里「服务器」一栏默认填着 `https://littleskin.cn/api/yggdrasil`
- 「注册」按钮能打开 LittleSkin 注册页

**失败表现**：只有两个按钮 / 点了没反应 / 白屏。白屏说明 `PageType.Auth` 没加载，查 `PageLaunchLeft` 的 `Case 4`。

### T-A2 安装器网络提示（custom.13）

1. 下载 → 服务器 → 点任意版本的 `Forge` 或 `NeoForge`
2. 看「加载器版本」下面那行灰字

**通过判据**：加载完成后文字末尾有「安装时要连官方仓库，国内建议先开加速器 / 代理。」

再故意制造失败（关掉代理、选一个连不上的网络）后点「开始下载」，看失败提示是否包含：
- 退出码
- 一行日志摘要（`java.net.*` 之类）
- 「请先开加速器（或代理）再重试」
- 「实在装不上可以改用原版 / Paper」

### T-A3 美西螈 mod 差异提示（custom.14）

**前置**：已经用「扫描其他启动器」转换过一次美西螈实例。

1. 在美西螈里给某个实例的 `mods` 加一个 jar（或删一个）
2. 回 PCL 点「扫描其他启动器」

**通过判据**：美西螈那一行出现「N 个的 mod 数量对不上，建议重新转换」。
点「全部添加」后出现红色的「重新转换 / 保持不动」确认框；选「重新转换」后，
PCL 侧 `versions\<实例名>\mods` 的 jar 数量应与美西螈侧一致。

**注意**：重新转换会**删掉 PCL 侧那个实例目录**再重建（走回收站），
PCL 里新产生的存档会没。测之前先把要保留的存档挪走。

### T-A4 添加已有的服务端目录（custom.15）

1. 联机页 → 服务器 → 「已装服务端」下拉右边点「添加已有」
2. 选一个**不是**通过 PCL 下载的服务端目录（自己搭的、从别处拷来的都行）
3. 列表里应出现该目录（标签是目录名），选它点「用这个开服」能启动

**通过判据**：能加进去、能启动、能看日志、能用控制台。

**失败表现**：选了个空目录时说「不像服务端目录」—— 这是预期的拒绝，不算 bug。

### T-A5 远程服务器 RCON（custom.16）

**前置**：找一个能改 `server.properties` 的服务端（本地也行，用来验证协议）。在它的
`server.properties` 里加三行：

```properties
enable-rcon=true
rcon.port=25575
rcon.password=test123
```

重启服务端（RCON 只在启动时读配置）。

1. 联机页 → 服务器 → 「远程服务器（RCON）」填地址 `127.0.0.1`、端口 `25575`、密码 `test123`
2. 点「连接」

**通过判据**：
- 状态行变成「已连接 127.0.0.1:25575（命令发往远程）」
- 点错了密码时提示「RCON 连接失败：密码错误」，而不是卡住或静默
- 连上后在上面的命令框发 `list`，控制台出现 `> list  [RCON]` 和玩家列表
- 发 `say 中文测试`（远程模式下）中文正常
- 点「断开」后状态回到「未连接」，再发命令会提示去连 RCON

**注意**：RCON 看不到服务端的实时日志（它只是请求-回应），只能看命令回显。

### T-A6 关闭启动器时的服务端行为（custom.17 / .18）

**先弄清原本的行为**：`ServerProc` 是普通子进程，PCL 没有杀它的代码，所以
**关掉启动器服务端不会死**，会继续在后台跑。问题是 PCL 重开后 `ServerProc` 变量丢了，
界面显示「未启动」，但服务端其实还在跑 —— 状态不一致，而且再也接管不了它的控制台。

1. 开一个本地服务端，确认控制台有输出
2. 关掉启动器 → 看弹窗

**通过判据**：
- 弹窗说明「让它继续跑 / 一起关掉」及各自后果
- 选「让它继续跑」→ PCL 退出，任务管理器里 java 进程**还在**，玩家还能进服
- 重开 PCL → 联机页那行显示「后台仍在运行（PID xxx，14:xx 启动）」而不是「未启动」
- 点「关闭服务器」→ 若服务端开着 RCON（新版开服会自动配），弹窗会说可以正常 stop，
  确认后 java 进程消失；连不上 RCON 时才退化成「只能强制结束」。细节见 **T-A7**
- 勾上「关闭启动器时一并关掉本机服务端」→ 重复第 2 步，选「一起关掉」，
  PCL 退出后 java 进程应该也没了

**注意**：勾选框默认**不勾**（= 让它继续跑）。关闭时的弹窗是每次都会问的，勾选框只决定
「静默退出（比如从托盘/快捷键退）时怎么做」。

### T-A7 RCON 接管（custom.19）

**目标**：启动器重启后也能给遗留的本机服务端发命令、优雅停服，不用强杀。

**前置**：这个能力依赖服务端开了 RCON。PCL 在「开本地服务端」时会**自动**往
`server.properties` 里写 `enable-rcon=true` / `rcon.port=25575` / 随机 `rcon.password`
（密码**默认不存设置**，写进文件即为权威源；接管时从文件现读）。
**所以必须用新版 PCL 重新开一次服**，老的服务端配置里没有这三行，接管不了。

1. 用 PCL 开一次本地服务端（新版会自动写 RCON 配置），确认能进游戏
2. 关掉 PCL，选「让它继续跑」
3. 重开 PCL → 进联机页

**通过判据**：
- 那行显示「后台仍在运行（PID …）」+ 控制台出现 `[RCON] 已自动连上 127.0.0.1:25575`
- **在上面命令框发 `say 中文测试`，游戏里能看到** —— 这一步就是「接管」成功的标志
- 点「关闭服务器」→ 弹窗应说「可以走 RCON 让它正常 stop」→ 确认后服务端优雅退出，
  java 进程消失，且**没有**走强杀

**失败表现**：
- 控制台没有 `[RCON] 已自动连上` → 说明 `server.properties` 里 RCON 没开，重开一次服
- 能连上但发命令报错 → 看是不是密码对不上（`rcon.password` 与服务端实际值不一致）

### T-A8 RCON 密码「用完即清」（custom.22）

**口径**：默认一次性输入，连上后清空，下次重输；不想重输才勾「记住密码」，勾的时候会有确认。

1. 不勾「记住密码」，填密码连一次远程 RCON
2. 连上后看密码框
3. 断开，再点「连接」
4. 勾上「记住密码」→ 看确认框 → 点「取消」
5. 再勾一次 → 点「我了解，记住」→ 关掉 PCL 重开

**通过判据**：
- 第 2 步：密码框**已被清空**（没有再留着明文，也不留圆点）
- 第 3 步：因为框是空的，且地址不是本机 → 提示「先填 RCON 密码」，不会拿别的密码去凑
- 第 4 步：出现风险确认框；点取消后**勾选状态回滚成未勾**
- 第 5 步：确认后密码框变成圆点 `••••••••`，重开 PCL 仍显示圆点、能直接连上
- 未勾「记住密码」时，「显示密码」是**灰的**（点不动）

**注意**：本机服务端是例外 —— 即使不勾记住，也能从 `server.properties` 现读密码自动接管，
这是**故意的**（否则每次重启启动器都要手输本机密码，反而没人用）。

## C. 需要第二台机器（VM 可）

> 这组**只能在两台机器上测**，本机单机测不了。VM 里要装 .NET Framework 4.8
> （Win10 自带 4.8，Win7 要手动装），能读到宿主机共享目录。

### T-C1 主机开服，VM 里的游戏连进来（局域网）

**目的**：确认服务端不是只能自己连。

1. 主机：联机页「开服」，等控制台出现 `Done (xx.xxxs)!`
2. 主机：`ipconfig` 记下局域网 IP（`192.168.x.x`），确认
   `server.properties` 里 `server-port=25565`、`online-mode=false`、`white-list=false`
3. VM：在游戏「多人游戏 → 直接连接」里填 `主机IP:25565`

**通过**：VM 能进服，主机控制台出现 `xxx joined the game`。

**失败排查**：
- 一直"连接超时" → 宿主机 Windows 防火墙拦了 java（首次开服会弹询问，要选"允许专用网络"）
- "Invalid session" → `online-mode` 还是 true，但 VM 用的是离线登录
- "You are not white-listed" → 白名单开着却没加人

### T-C2 VM 连主机的 RCON（远程模式）

**目的**：这是「远程服务器」分支唯一的真实场景，本机测不出来。

1. 主机：`server.properties` 确保有 `enable-rcon=true` / `rcon.port=25575` / `rcon.password=...`，
   重启服务端
2. 主机：**先把本机服务端停掉**（否则联机页会走本机 stdin，测不到 RCON）
3. 主机 PCL →「远程服务器（RCON）」填 `主机IP` / `25575` / 密码 → 连接
4. 看玩家名单区

**通过**：
- 名单区显示「远程服务器：… 远程读不到完整名单，所以这里不列出来」
- 输入玩家名点「添加玩家」→ 主机控制台出现 `Added xxx to the whitelist`（或 `whitelist add` 回显）
- 命令框发 `list` → 控制台里出现 `[RCON]` 标记的回显

**重点验**：主机本机**同时有服务端目录**时，名单区**不能**显示本机那几个玩家
（这是 custom.20 修的 bug，最容易回归）。

### T-C3 干净机从零编译

**目的**：验证换台机器还能不能编出来（R-02 风险）。

1. VM 里只拷 `gongtong\` 整个目录（含 `_tools\`，1.7 GB，可从备份盘拿）
2. **不要拷** `obj` / `bin` / `PCL-custom`（模拟全新环境）
3. 跑 `cd pcl-src && build.cmd`（**不带 `-NoRestore`** —— 没有 obj 时必须先还原）
4. 看是否出 `PCL-custom\Plain Craft Launcher 2.exe`

**通过**：0 错误、出 exe、`versions\<label>\build-info.txt` 里的 sha256 与实算一致。

**已知会踩**：不带 `-NoRestore` 会从 `_tools\nuget` 取包，所以 `_tools` 必须完整。

### T-C4 断网编译

**目的**：判断工具链是否真自足。

1. 在 T-C3 通过的前提下，断开 VM 网络
2. 删掉 `obj` / `bin`，再跑一次 `build.cmd`

**通过**：仍能编出来。

**失败含义**：还有包没进 `_tools\nuget`，恢复环境时必须联网 —— 属于要补的风险项。
