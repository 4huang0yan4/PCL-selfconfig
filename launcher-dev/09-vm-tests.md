状态：`[待测试]` T-05 / T-06，VM 可用，2026-10-28 编写、尚未执行

> 为什么非要两台机器：陶瓦用全局文件锁 `%TEMP%\terracotta\terracotta.lock`（前 2 字节存端口），
> **一台机器只能有一个守护进程、一份状态**，同机开两个启动器测不出游客端。VM 就是那第二台。

   不要改 VM 里的 `.minecraft` 指向宿主目录。
3. 网络二选一，**先记下用的哪种**，写进证据表：
   - A 桥接同一局域网
   - B VM 走 USB 共享手机移动数据（10-27 的 T-01 用的这个）
4. 两机各自能进游戏并「对局域网开放」。

## 三、T-06 长时稳定性（≥ 30 分钟）

1. 建好房、游客进入，两人待在同一区块（避免区块加载差异干扰）。
2. 每 5 分钟记一次两端启动器进程内存：任务管理器 →「详细信息」→「内存（专用工作集）」。
3. 判据：**30 分钟内不掉线**，且内存有波动但无持续单向增长（允许 ±10% 抖动）。

## 四、取证边界（2026-10-28 实测更正，很重要）

**智能体只能读宿主侧，读不到 VM 内部。** 别按"跨机也能抓状态"排步骤：

| 想读的东西 | 能不能 | 原因 |
|---|---|---|
| 宿主陶瓦 `/state` | 能 | `curl --noproxy '*' http://127.0.0.1:<锁端口>/state` |
| 宿主 `PCL\Log1.txt` | 能 | 本地文件 |
| 宿主进程/端口 | 能 | `ps -W`、`netstat -ano` |
| **VM 陶瓦 `/state`** | **不能** | 陶瓦 HTTP 只绑 `127.0.0.1`，VM 的 loopback 出不了 VM |
| **VM 的日志/截图** | **不能** | 除非放进共享文件夹（可轮询文件）或由用户口述/拍照 |
| **宿主断网期间的实时现象** | 不能 | 智能体调模型要走公网，一断网就失去响应能力 |

**由此定的分工**：让**宿主当房主**（可实时取证），**VM 当断网游客**——这正好就是最该测的"弱网游客"场景；
VM 侧只看提示文案，由用户念给智能体，或把 VM 的 `PCL\Log1.txt` 丢进共享文件夹。

## 六、已知陷阱（省得白测一轮）

- **建房前必须先在游戏里「对局域网开放」**，否则永久停在 `host-scanning`。
- `/panic?peaceful=true` 不回响应（服务端直接 `exit(0)`），客户端看到连接重置是正常的，别当失败重试。
- 访问 `127.0.0.1` 必须显式禁代理，否则被系统代理劫持返回**假 502**。
- 房间码末位是校验位，`U/0000-0000-0000-0000` 其实**合法**（0 能被 7 整除），造错码用例要改末位。
- VM 里若装了旧版启动器，先清掉 `PCL\Terracotta\` 再复制，避免新旧二进制混用。
