# 11 T-04：陶瓦与 HMCL 并存

状态：`[待测试]` 2026-10-28 15:47 起测。HMCL `3.15.2`（`<本地>\ls\HMCL-3.15.2.exe`）；PCL、陶瓦、frpc 均未运行，起点干净。
最后更新：2026-10-28

> 陶瓦用**全局文件锁** `%TEMP%\terracotta\terracotta.lock`（前 2 字节存端口），一台机器只能有一个守护进程、一份状态。
> HMCL 也内置陶瓦联机，所以两者同时用时**必然共用同一个守护进程**。要验的是：后开的那方能"接管"而不是起第二个守护进程，
> 且两边界面显示的状态不自相矛盾（比如一边说建房成功、另一边说未运行）。

## 一、要盯的东西

| 观察点 | 怎么看 | 期望 |
|---|---|---|
| 守护进程数量 | `ps -W \| grep terracotta` | **始终只有 1 个** `terracotta-*.exe` |
| 锁端口 | `%TEMP%\terracotta\terracotta.lock` 前 2 字节 | 不随第二个启动器改变 |
| 状态一致性 | `curl --noproxy '*' http://127.0.0.1:<port>/state` | `room` / `state` 对两边是同一份 |
| 起第二个守护进程的迹象 | 进程数变 2、或锁端口变化 | 视为**不通过** |

## 二、步骤

| 步 | 操作 | 记录 |
|---|---|---|
| H1 | 用 **HMCL** 启动游戏、开存档、「对局域网开放」，在 HMCL 里建房 | 是否出码、耗时、HMCL 显示的码 |
| H2 | **HMCL 保持运行**，开 **PCL**，进「联机」→「创建房间」 | PCL 能否出码；有没有报"端口被占用/已在运行" |
| H3 | 两边各自的界面状态 | 是否指向**同一个房间码**；有矛盾就截图 |
| H4 | 在 PCL 点「取消 / 复位」 | HMCL 那边是否跟着变（共用状态应一起变） |
| H5 | 反向：先在 PCL 建房，再开 HMCL 建房 | 是否同样复用、状态是否一致 |

## 三、判定

- **通过**：全程只有 1 个守护进程、锁端口不变、两边状态与房间码一致、复位对双方同时生效。
- **不通过**：出现第二个守护进程、锁端口变化、两边状态矛盾、或一方直接报错无法接管。

## 四、已知陷阱

- 建房前必须先在游戏里「对局域网开放」，否则停在 `host-scanning`，看起来像 HMCL/PCL 抢锁，其实是没开局域网。
- HMCL 首次用陶瓦可能要自行下载（走它的更新源），先给它联网跑通一次，再开始记录。
- 两边**共用一个局域网世界**：只有最后「对局域网开放」的那个世界会被陶瓦发现，开多个存档容易连错世界。
- 复位后房间码作废（PCL 侧 `custom.2` 起会自动清空输入框），别拿旧码去测加入。

## 五、实测记录（2026-10-28 17:10，`custom.3`）

环境：HMCL `3.15.2` 先建房，随后在**同一台机器**开 PCL 建房。

**共用守护进程 — 通过**：

```
terracotta 进程数 = 1（PID 5060，17:08:21 启动，全程未变）
terracotta.lock 端口 = 16408，未变
两次建房都在同一运行目录 2026-10-28-17-08-21-5060
```

即 PCL 没有起第二个守护进程，确实复用了 HMCL 那个。

**但"接管"的实质是重建房间，先建那方的码当场作废**。同一进程内出现两次 `HostStarting → HostOk`：

```
HostStarting code=U/50DB-TQHT-X8QS-GVNW → HostOk     ← HMCL 建的
HostStarting code=U/JTWH-F91Y-5EZB-7N05 → HostOk     ← PCL 覆盖，换码
```

当前 `/state` 的 `room` 为 `U/JTWH-F91Y-5EZB-7N05`。用户确认：**后建的覆盖先建的，界面随之变为 PCL 的码**。

**判定**：

- 锁共用、状态单份（后建覆盖）= 符合预期，**T-04 主判通过**。
- **文案问题**：PCL 提示「已经创建好了」，字面意思是"复用现有房间、码没变"，实际是"接管并重新建房、旧码失效"。
  若有朋友已拿着先建那方的码在等，一按就会静默失效，双方都无提示。**记为改进项**：
  接管时应明说「已接管现有房间，房间码已更换为 xxx」。

**H4 复位传播 — 通过**：在 PCL 点「取消 / 复位」后，`/state` 从 `host-ok` 变为 `{"index":12,"state":"waiting"}`（`profiles` 清空），
`easytier-core` 随之退出，陶瓦守护进程仍存活（PID 5060）。用户确认 **HMCL 界面同步清空、回到「创建房间 / 加入房间」选择页**。
即共用的是同一份状态，复位对双方同时生效。

**H5 反向顺序**：未单独跑——H1–H4 已覆盖"共用进程 + 单份状态 + 双向复位"三件事，反向只影响谁先谁后，不改变结论。

## 六、T-04 结论：**通过**（附一条文案改进）

| 检查项 | 结果 |
|---|---|
| 守护进程数量 | 全程 1 个（PID 5060）✅ |
| 锁端口 | 16408 不变 ✅ |
| 状态是否单份 | 是，后建覆盖先建 ✅ |
| 复位是否双向生效 | 是，PCL 复位 → HMCL 回到选择页 ✅ |
| 提示文案 | 「已经创建好了」与"换码"事实不符 ⚠️ 记改进项 |
